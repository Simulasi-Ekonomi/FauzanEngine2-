# FauzanEngine Production Backend Readiness Gate

## Rule of engagement

No new application, website, dashboard, or graphical control surface may be presented as an implementation deliverable before this gate passes. Existing control-plane code remains outside the active engine implementation scope. The only permitted graphical work before the gate is an engine-owned executable test/vertical slice used to validate rendering and gameplay.

### Movement authority addendum

`MovementAuthorityGate` now provides a bounded caller-reset per-frame claim table for SceneWorld entities. `GridRouteFollower::StepGuarded` requests `KinematicRoute` authority and `SkeletalAnimationController::AdvanceApplyRootMotionGuarded` requests `SkeletalRoot` authority before either can mutate a world transform. A conflicting authority is rejected before movement, palette, player time, route progress, or world output changes; same-authority repeated access is permitted and `BeginFrame` resets claims. `NeoRuntime` owns one gate, resets it on each unpaused tick before route work, and invokes route movement through the guarded path; its accessor exposes the gate for explicit same-frame coordination. Release and AddressSanitizer smoke prove route movement succeeds, skeletal root motion is rejected in that same frame without changing its time or transform, skeletal motion succeeds after reset, a later route claim conflicts, and runtime route ticks conflict while active but release the claim on the next no-route tick. `GridRouteFollower` exposes a bounded `RouteIntent`/receipt seam, and `RouteRootMotionAdapter` uses it to make guarded skeletal root motion the sole planar transform writer. `NeoRuntime` now offers a default-off, mutually-exclusive skeletal static-route mode limited to one straight two-cell clamp route with a direction assertion; its dedicated smoke proves partial/arrival motion, pause, goal stability, gate reset, explicit replan rejection, shutdown, wrong-direction and blocked-target preservation. It has no multi-segment/loop route contract, root rotation, clip asset pipeline, actor/NPC automation, collision/physics, prediction, multiplayer, or renderer binding. The readiness gate remains **not passed**.

## Required evidence

| Domain | Completion evidence required before a production-ready claim |
|---|---|
| Canonical runtime | A single `NeoRuntime` owns game selection, fixed/update ticks, scene lifetime, asset lifetime, graceful shutdown, and deterministic invalid-state errors. |
| Scene and entities | Deterministic entity IDs, transforms, component lifecycle, prefab/scene serialization, bounded load errors, and Release plus AddressSanitizer smoke coverage. |
| Renderer | A selected backend creates a real surface/device, uploads a mesh and texture, renders camera-visible geometry, executes material/light paths, releases resources correctly, and returns fail-closed capability errors when unavailable. |
| Asset bytes | Mesh, texture, material, audio, prefab, and scene bytes are content-hashed, imported with explicit limits, dependency-checked, and converted to renderer-ready resources. |
| Game runtime | Input, audio, save/load, telemetry outbox, fraud/economy rules, and a Farm graphical vertical slice execute against the same canonical runtime. |
| Templates | Every advertised production-capable template is executable, not merely catalogued, and has bounded deterministic smoke coverage. |
| Packaging | The canonical Android subset compiles with pinned SDK/NDK/Java, produces a debug APK and signed release AAB, and has device/emulator evidence. |
| Release authority | Real runtime envelopes are forwarded by a token-holding trusted host, server-side reconciliation/appeal governance is present, and no credentials live in game assets or runtime saves. |
