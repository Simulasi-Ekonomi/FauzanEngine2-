## Perbaikan yang Tervalidasi

Build desktop menggunakan compatibility SIMD portable, sedangkan Android/ARM tetap memakai intrinsic NEON. Library engine tidak lagi memasukkan source Android, EGL, GLES, Vulkan, atau test executable ke target headless. XPBD kini membangun collider statis ke broadphase, memiliki enum constraint yang selaras dengan API public, menyimpan buffer solve per worker, menulis rotasi kembali ke ECS, memakai timestep solver yang sama dengan integrasi, dan hanya menyelesaikan cloth sekali per step.

Regression executable juga mengeksekusi jarak, fixed, spherical joint, cloth patch, fracture terjadwal, serialization/deserialization, overlap query, fallback GPU broadphase, writeback dua frame tanpa kontak, serta penghapusan ECS swap-back. Jalur yang dahulu kosong pada API tersebut sekarang memiliki implementasi runtime.

Validasi collision-heavy AddressSanitizer sempat menemukan overflow heap pada graph coloring. Penyebabnya adalah warna disimpan per entity, kemudian dipakai kembali seolah-olah warna tersebut milik setiap kontak. Implementasi kini menyimpan mask warna per entity dan warna per kontak, sehingga bucket indeks tidak lagi menulis melebihi `m_SortedContactIndices`. Merge deferred delta juga telah diubah dari akses SIMD AoS yang tidak valid menjadi merge per entitas. Regression sanitizer berikutnya juga menemukan array chunk `ArchetypeManager` tidak dibebaskan; manager sekarang memiliki destructor eksplisit dan `DestroyEntity` menjalankan swap-back sambil memperbarui indeks entity.

Setelah traversal grid active-cell ditambahkan, stress collision-heavy 100K kembali lulus AddressSanitizer dengan rata-rata 202.289,3 kontak/frame. Mode sanitizer memiliki peak RSS 221,37 MiB dan tidak dipakai sebagai ukuran performa release.

Optimasi berikutnya yang dipertahankan tidak menurunkan coverage declared contact. Manifold cache memakai lookup-or-create satu lintasan dan handle ber-generasi agar commit warm-start solver tidak mencari pasangan yang sama kembali. Kandidat grid dikumpulkan paralel lalu di-emit serial menurut urutan deterministik. State union-find yang tidak lagi dikonsumsi setelah graph coloring langsung telah dihapus. Merge deferred delta sekarang dipartisi pada rentang entitas eksklusif namun menjumlahkan worker dalam urutan yang sama; hasilnya regression, determinisme, dan AddressSanitizer tetap lulus, sementara fase merge turun dari sekitar 4,7 ms menjadi sekitar 1,4 ms pada benchmark berinstrumentasi.

Batch warna terbesar pada stress ini berisi sekitar 43 ribu kontak. Batch warna tersebut kini dipecah ke task statis hanya setelah graph memastikan tidak ada dua constraint dalam warna yang sama berbagi entitas. Perubahan ini menurunkan fase solver terukur dari sekitar 16–18 ms menjadi sekitar 12–14 ms pada run berinstrumentasi. `bench_100k` juga dapat membedakan runtime dengan dan tanpa instrumentasi fase agar angka headline tidak menyamarkan biaya observability.

Pada gather grid dense, indeks pasangan berasal dari linked-list yang hanya dibangun dari `m_activeFlatEntities`; pasangan sel-sama dan sel-tetangga juga menjamin dua indeks berbeda. Guard batas dan kesamaan indeks yang sebelumnya dieksekusi untuk setiap kandidat hot-path karena itu redundant pada jalur internal ini. Counter kandidat sekarang diakumulasi di variabel lokal per worker lalu dikomit sekali setelah rentang gather selesai. Perubahan tersebut mempertahankan 202.044 kontak/frame pada tiga run non-instrumented dan lulus regression, determinisme, serta AddressSanitizer.

Kandidat yang keluar dari gather dense-grid juga sudah berada dalam rentang entity aktif serta dinormalisasi menurut indeks. Emit serial menerima fast path canonical untuk kandidat tersebut dan tidak lagi mengeksekusi guard batas maupun swap indeks yang tetap dipertahankan pada jalur BVH/CCD/fallback. Tiga run release mempertahankan 202.044 kontak/frame dan berada pada kisaran 43,669–47,767 ms; regression, determinisme, dan AddressSanitizer lulus.

Tahap emit dense-grid kemudian dipecah tanpa mengubah urutan kandidat atau urutan associator manifold. Setelah gather paralel selesai, setiap worker menulis payload kontak ke rentang `ContactBlock` eksklusif yang telah dihitung secara deterministik. Associator manifold tetap berjalan serial menurut urutan worker dan kandidat asli, sehingga urutan insert cache serta warm-start tidak berubah. Staging ini menghapus pembacaan flat-array, normal/contact-point, dan penulisan payload dari critical path serial. Pada timing berinstrumentasi, emit turun dari sekitar 24,305 ms menjadi 14,988 ms dan broadphase dari 29,012 ms menjadi 21,338 ms; tiga run Release berada pada 42,049–45,078 ms untuk 202.044 kontak/frame. Regression, determinisme, dan AddressSanitizer lulus, dengan benchmark ASAN penuh mencatat 201.941,6 kontak/frame tanpa laporan sanitizer.

Profil cache manifold kini mencatat kedalaman probe hanya bila mode profiling benchmark aktif. Pada stress collision-heavy, cache menunjukkan rata-rata **1,457 probe per lookup** dan kedalaman maksimum **33** untuk sekitar 203.807 lookup/frame (22.387 hit dan 181.420 create attempt). Metrik ini tidak membebani runtime normal. Temuan tersebut menunjukkan bahwa pengurangan probe linear semata bukan jalur utama untuk mengejar puluhan milidetik yang masih tersisa; jalur serial emit/cache dan narrowphase tetap perlu direstrukturisasi dengan tetap menjaga warm-start.

Eksperimen cache manifold yang membesarkan kapasitas, membagi cache per worker, atau mereset lambda ditolak karena coverage turun di bawah batas validasi sekitar 200 ribu kontak/frame atau waktu memburuk. Eksperimen hash 32-bit, key cache terpisah, reciprocal square root untuk narrowphase, inlining paksa lookup cache, granularitas task warna 2.048/8.192, dan reordering fisik stream kontak sesudah graph coloring juga ditolak atas dasar benchmark nyata. Reordering terakhir memang menghapus dereference indeks di tiga iterasi solver, tetapi biaya copy penuh stream SoA menaikkan rata-rata menjadi 58,975 ms dan menaikkan RSS menjadi 134,85 MiB.

Eksperimen dua iterasi solver kontak menunjukkan bahwa sekadar mengurangi iterasi tidak dapat diterima sebagai jalan pintas target: runtime memang turun menjadi 12,886 ms, tetapi cakupan rata-rata turun menjadi 178.681,9 kontak/frame. Perubahan dibatalkan dan source default tetap memakai tiga iterasi.

Cache manifold direct-slot serial yang memperbesar state ke ukuran tabel stamp juga ditolak. Lookup tetap deterministik dan serial, namun churn slot menaikkan peak memory ke 117,00 MiB, menghasilkan 503,4 rejection/frame, menurunkan cakupan ke 195.462,7 kontak/frame, dan memperburuk runtime menjadi 21,590 ms. Cache compact beserta eviction generasi sebelumnya telah dipulihkan.

Restitusi sekali per step juga ditolak. Menghindari dua loop restitution berikutnya memang menurunkan runtime menjadi 15,792 ms, tetapi simulasi kehilangan cakupan hingga hanya 154.688,5 kontak/frame. Koreksi posisi dan restitusi tiga iterasi tetap menjadi kontrak default yang tervalidasi.

Penolakan pasangan sel melalui AABB konservatif mengurangi kandidat dense-grid dari sekitar 479 ribu menjadi 384 ribu per frame tanpa menurunkan coverage. Akan tetapi, alokasi dan pembaruan metadata sel menaikkan broadphase terinstrumentasi menjadi 9,097 ms dan tiga run Release menjadi 19,548–20,860 ms. Implementasi dihapus karena optimasi penuh harus menang pada full-frame, bukan hanya pada counter kandidat.

Validity mask SIMD solver kini memakai horizontal-any native: NEON mereduksi dua half-lane tanpa store sementara, SSE2 memakai `_mm_movemask_ps`, dan fallback scalar meng-OR empat lane. Perubahan mempertahankan 202.416 kontak/frame pada tiga run Release (18,611–19,084 ms) serta lulus regression, determinisme, dan AddressSanitizer stress 100K tanpa laporan sanitizer.

Split linked-list awake/static pada dense-grid juga telah diuji. Meskipun menghilangkan pemeriksaan statis-statis secara eksplisit dan mempertahankan coverage, build list kedua serta cabang ownership lintas sel menaikkan waktu menjadi 20,447 ms. Source kembali memakai satu linked-list per sel.

Loop kontak sebelumnya adalah Jacobi terhadap `m_ThreadDeltas`: setiap iterasi membaca `ContactBlock` yang sama dan tidak mengonsumsi deferred delta hingga `MergeThreadDeltas` sesudah seluruh loop. Tiga iterasi tersebut karena itu menghasilkan koreksi lane yang identik. Solver kini menjalankan satu pass deterministik, lalu memberi bobot tiga pada delta posisi, rotasi, kecepatan, dan angular-velocity sebelum merge; commit lambda manifold tetap berasal dari solve lane yang identik. Coverage tetap sekitar 202.414 kontak/frame, phase solver berinstrumentasi turun dari sekitar 5,874 menjadi 2,246 ms, dan validation Release/AddressSanitizer lulus. Perubahan ini bukan pengurangan jumlah iterasi fisik yang diam-diam; perubahan hanya menghapus kerja pengulangan input yang tidak dibaca oleh implementasi Jacobi sebelumnya.

Cache graph warna yang membandingkan urutan pasangan secara exact juga ditolak. Workload bergerak mengubah cukup banyak urutan pasangan antar-frame sehingga cache harus rebuild; compare snapshot menambah kerja dan phase graph tercatat 2,219 ms. Source kembali membangun graph secara langsung setiap frame.

Dispatch Jacobi tanpa graph-coloring juga ditolak. Meskipun deferred delta worker-local menjaga determinisme dan coverage tetap sekitar 202.408 kontak/frame, satu batch sekitar 202 ribu kontak membesarkan buffer lane dan meningkatkan RSS ke 146,51 MiB serta waktu ke 17,558 ms. Graph-colored batch yang lebih kecil dipulihkan.

Micro-batch 4K pada dispatch colorless juga tidak cukup untuk mengatasi regresi: coverage tetap, tetapi runtime 17,010 ms dan RSS 146,75 MiB. Graph-colored dispatch tetap dipertahankan.

Pemilihan warna first-free kini menggunakan bit-scan pada komplemen mask dua entitas, dengan fallback warna nol bila seluruh rentang warna terpakai. Semantik warna dan fallback tidak berubah, tetapi loop linear per warna dihilangkan. Coverage tetap 202.414 kontak/frame, phase graph turun ke 1,515 ms, dan tiga run Release berada pada 14,204–14,698 ms; regression, determinisme, serta stress AddressSanitizer lulus.

Meningkatkan kapasitas manifold hingga setara tabel stamp juga ditolak. Probing linear tabel stamp menjadi jenuh sebelum cache dapat memberi manfaat: rejection mencapai sekitar 73.643/frame, coverage turun ke 191.600 kontak/frame, RSS naik ke 116,67 MiB, dan runtime menjadi 23,428 ms. Kapasitas compact 262.144 dipulihkan.

Build `-ffast-math` terpisah juga ditolak: ia mencatat 201.847,6 kontak/frame dan 16,828 ms. Walaupun test kecil lulus, konfigurasi tersebut gagal gerbang coverage dan performa terhadap baseline retained sehingga tidak diterapkan pada toolchain portable maupun Android.

Build Release dengan link-time optimization juga diukur terpisah. Coverage tetap 202.414 kontak/frame, tetapi runtime 15,804 ms tidak mengalahkan baseline retained; konfigurasi tidak dijadikan default.

Diagnostik dengan associator manifold staged dimatikan sementara mencapai 10,520 ms dan emit 2,610 ms, dibanding baseline yang mempertahankan warm-start/cache. Jalur tersebut tidak aman untuk dipertahankan sebagai runtime produksi karena tidak mengasosiasikan manifold dan tidak membawa lambda warm-start. Pengukuran hanya menetapkan bahwa associator serial/caching merupakan biaya arsitektural dominan berikutnya; source langsung dipulihkan dan kembali lulus regression, determinisme, serta benchmark.

Prefetch slot stamp manifold selama staging paralel juga diuji tanpa mengubah urutan lookup serial. Coverage tidak berubah, tetapi runtime 15,717 ms tidak mengalahkan baseline; hint spekulatif dihapus.

Associator manifold dense-grid kini di-shard menurut hash pasangan. Kandidat diroute deterministik ke delapan shard, lookup/insert dalam masing-masing shard tetap serial, lalu shard independen berjalan paralel tanpa atomics. Cache shard memiliki stamp dan storage sendiri; indeks manifold dense diberi flag eksplisit agar writeback lambda solver kembali ke shard yang tepat. Tiga run Release berada di 11,339–13,054 ms pada 201.433,6 kontak/frame dengan warm-start hit tetap tercatat. Regression, determinisme, stress AddressSanitizer, dan kontrol no-overlap 1,838 ms lulus. Perbaikan ini belum cukup untuk klaim target wajib <10 ms.

Admission manifold tertunda untuk pasangan yang terlihat dua frame berturut-turut ditolak. Walaupun contact coverage dan test kecil bertahan, runtime menjadi 14,529 ms dan RSS 126,20 MiB. Associator shard kembali mengadmit pasangan segera.

Empat shard juga diuji pada source yang sama. Walaupun coverage tidak berubah, runtime 13,950 ms dan P95 35,478 ms lebih buruk; konfigurasi delapan shard dipulihkan.

Routing contact index per-worker/per-shard saat staging juga diuji untuk menghapus pass serial pengelompokan. Hasilnya 12,762 ms pada coverage yang sama, tidak mengalahkan routing serial, sehingga source kembali ke jalur yang lebih sederhana.

Fusi stage-payload dengan associator shard menghasilkan 19,013 ms dan dibatalkan; barrier stage terpisah dipulihkan. Cache dense-shard yang dibesarkan hingga total sebesar tabel stamp juga ditolak: meski hit naik, ia mencapai 15,658 ms, 7,5 rejection/frame, dan RSS 123,48 MiB. Kapasitas compact retained dipulihkan.

Admission manifold ter-sampling 1/8 sebagai diagnostik mencatat 13,149 ms pada 202.238 kontak/frame. Karena ia mengurangi cakupan warm-start dan tidak mengalahkan baseline retained, sakelar eksperimen telah dihapus dari source produksi.

Direct-slot persistent per dense-shard juga ditolak. Collision table mencapai sekitar 66.384 rejection/frame, menghasilkan 16,292 ms dan RSS 123,19 MiB pada 200.639,6 kontak/frame. Cache compact dengan reset terkontrol telah dipulihkan.

## Catatan Pemulihan Sandbox

Pada 22 Agustus 2026, reset sandbox menghapus tree build dan sebagian source pendukung yang tidak termasuk dalam file perubahan terakhir. Tree lengkap dipulihkan secara pasif dari arsip FauzanEngine milik pengguna, lalu source XPBD staging yang telah dipertahankan, benchmark, backlog, dan laporan ditimpa kembali. Konfigurasi CMake headless, header kompatibilitas SIMD x86/NEON, adapter raw job scheduler, test regression/determinisme, serta lifecycle `ArchetypeManager` juga dipulihkan agar executable dapat dibangun ulang.

Validasi ulang menghasilkan regression `contacts=1`, `bytes=196644`, `overlaps=2`, serta determinisme `108` byte. Ukuran serialisasi regression berubah karena skenario recovery sengaja mengaktifkan dense-grid dengan body filler terpisah, bukan karena klaim kompatibilitas state lama. AddressSanitizer lulus untuk regression, determinisme, dan benchmark collision-heavy 10 frame dengan 202.416 kontak/frame tanpa laporan sanitizer atau leak. Angka Release pasca-pemulihan berada pada 20,249–21,312 ms, tetap di atas target wajib 10 ms; angka tersebut didokumentasikan sebagai baseline recovery dan tidak menggantikan tuntutan validasi lanjutan pada source/runtime kanonik.

## Batas Klaim Saat Ini

Target **100K entity <10 ms** baru terbukti untuk skenario 10% awake tanpa overlap yang dicatat di atas. Run tersebut sudah memasukkan writeback ECS pada jalur tanpa kontak; posisi body aktif tidak kembali ke state lama pada frame berikutnya. Target tersebut **belum terbukti** untuk 50% awake maupun collision-heavy, dan target ideal **<3 ms belum terpenuhi**. Pada workload collision-heavy yang dinyatakan, biaya dominan yang tersisa berada pada narrowphase/grid traversal dan emit/cache manifold; optimasi lanjutan harus mengurangi dua jalur tersebut tanpa mengurangi jumlah kontak yang seharusnya diproses.
