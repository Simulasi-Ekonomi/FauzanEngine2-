# FauzanEngine Canonical Capability Audit — 23 Agustus 2026

## Scope dan aturan interpretasi

Audit ini membaca target yang benar-benar disusun oleh `Source/NeoEngine/CMakeLists.txt`, source runtime/agent kanonis, dan bukti smoke yang tersedia. Istilah **terbukti** berarti terdapat target executable yang telah lulus dalam pekerjaan sebelumnya atau regresi terbaru; istilah tersebut tidak berarti siap rilis. Header atau direktori legacy yang tidak masuk daftar source CMake tidak diperlakukan sebagai kemampuan engine aktif.

### Addendum skeletal CPU — 24 Agustus 2026

`Skeleton` kanonis kini membatasi hierarchy pada 64 bone, menghitung global bind pose statis, menurunkan inverse bind affine secara atomik, dan mengevaluasi palette CPU dari local pose yang diberikan caller dengan rumus `globalPose × inverseBind`. `SkeletalPoseClip` mengisi local pose caller itu dari hingga 64 track TRS / 128 keyframe per track melalui interpolasi linear translation/scale dan normalized quaternion lerp; waktu negatif maupun track tidak lengkap tidak mengganti output. Sampling loop-nya caller-invoked, menggunakan maksimum durasi track yang positif, dan menolak clip statis tanpa mutasi. Ia juga memiliki blend dua clip caller-invoked yang mengharuskan track compatible dan faktor `[0,1]`, serta membuktikan root `(1,4)→2.5` dan head `(90°,0°)→45°`. `SkeletalPosePlayer` menambah time/pause/speed/clamp-loop local yang caller-invoked serta menyalin snapshot clip lengkap saat bind; advance delta hingga satu detik membangun output kandidat sebelum commit, dan sumber clip boleh keluar scope sesudah bind. `SkeletalAnimationController` menyalin Skeleton/player snapshot dan menghubungkan advance ke palette serta candidate-only skinning posisi-normal; root track tiga-bone menghasilkan palette head x=1 pada 0.5 detik, kemudian vertex `(0,2,3)` menjadi `(1,2,3)`, dan x=2 di terminal, sambil memelihara state ketika reinit clip tidak compatible atau skinning bone index invalid ditolak. Controller juga mengekstrak root-motion translasi clamp dan loop bounded: clamp delta x `1,0,1,0` pada half-time, pause, speed-two terminal, dan terminal clamp; loop membuktikan one-wrap x=3 dan multi-wrap x=6 tanpa diskontinuitas. Delta ini dapat diterapkan ke SceneWorld candidate: clamp entity x=10 menjadi x=11, loop one-wrap menjadi x=13, dan multi-wrap menjadi x=19 sementara entity invalid tidak mengubah world/controller. Pada jalur aplikasi entity, palette dibuat in-place dengan membuang translasi root relatif terhadap clip start sehingga head palette tetap x=0 dan pergerakan tidak terhitung ganda. Smoke Release dan AddressSanitizer membuktikan root half-translation/head rotation 90 derajat serta wrap `t=1.5` ke pose `t=0.5`, pause, speed dua kali, terminal clamp, loop player, kelangsungan snapshot setelah sumber keluar scope, jalur keyframe→bind/inverse/palette→posisi dan normal CPU head `(0,2,3)/(1,0,0)` ke `(1,2,3)/(0,1,0)`, identity palette pada bind pose, translasi head yang berubah, posisi vertex 100%-head dari `(1,2,3)` ke `(1,2,4)` melalui `Skinning`, dan normal transform inverse-transpose di bawah skala non-uniform. Jalur normal menolak zero normal, count salah, linear singular, atau matrix projective sembari mempertahankan output sebelumnya; jalur skeleton menolak pose-count salah, pose non-affine, inverse bind belum tersedia, bind singular, dan bone index skinning invalid. Ini belum merupakan runtime animation lengkap: tidak ada NeoRuntime clock/tick, autoplay, parameterized blend tree/state machine/additive layer, retargeting, root rotation/navigation/physics application, mesh binding, tangent skinning, renderer integration, ataupun GPU palette/upload.

### Addendum authority movement — 24 Agustus 2026

Route kinematik dan root-motion skeletal tidak lagi dibiarkan menulis transform SceneWorld yang sama secara diam-diam ketika caller menggunakan jalur guarded. `MovementAuthorityGate` membatasi claim per entity per frame pada `KinematicRoute` atau `SkeletalRoot`, menolak konflik sebelum mutasi, mengizinkan reuse authority yang sama, dan di-reset eksplisit melalui `BeginFrame`. `NeoRuntime` kini memiliki satu gate dan meresetnya di setiap unpaused tick sebelum route motion guarded; smoke membuktikan claim route aktif konflik dengan skeletal pada tick tersebut, lalu dibersihkan pada tick goal-stable berikutnya. `GridRouteFollower::PeekIntent` dan `CommitIntent` memisahkan pembentukan snapshot route dari cursor commit, sedangkan `RouteRootMotionAdapter` memakai kandidat follower/controller/world/authority/palette untuk memanggil root motion guarded sebagai satu-satunya writer lalu commit satu cursor pada arrival. Direction mismatch, claim `KinematicRoute`, dan target terblokir menolak transaksi tanpa perubahan caller. `NeoRuntime` sekarang dapat memiliki mode skeletal static route default-off yang eksklusif terhadap kinematic route dan dibatasi dua cell lurus, clamp, serta direction assertion; smoke membuktikan lifecycle partial/pause/goal/reset/replan-reject/shutdown. Dengan demikian, ini adalah fondasi arbitration—not NPC locomotion, steering, path-animation synchronization penuh, atau multiplayer movement authority.

## Temuan code yang tidak boleh dianggap ready

`AgentOrchestrator.h` merupakan orchestrator header-only legacy yang menerima handler bebas dan tidak masuk source CMake kanonis. Ia tidak memiliki typed capability, thread safety, audit trail, context budget, approval, sandboxing, maupun boundary authority. Oleh sebab itu ia tidak boleh dipakai untuk mengeksekusi prompt atau tool game. `OpenCodeIntegration.cpp` dan `ItemSerialTracker.cpp` juga masih mengandung penanda placeholder, namun keduanya tidak masuk target source aktif saat audit ini.

`FarmWorldTool::PopulateScene()` kini mengikat entity character, building, dan NPC. `Tick()` menyinkronkan transform NPC deterministik; perubahan character dan lifecycle building juga disinkronkan melalui `SyncScene()`. `farm_scene_sync_smoke` membuktikan pergerakan NPC, perubahan character, serta create/remove building di SceneWorld pada Release dan AddressSanitizer. `FarmRenderAdapter` kini merender tile terrain serta actor melalui `RenderCamera` dan `SpriteBatch`, tetapi masih membaca state Farm world alih-alih merender entity `SceneWorld`; karena itu scene binding ini belum menjadi renderer scene graph, animation system, atau client presentation lengkap.

## Kesimpulan readiness

Renderer menjawab **ya, berfungsi sebagai proof headless CPU serta proof Vulkan terpisah**, tetapi **tidak** sebagai renderer game rilis terintegrasi. World creation dan NPC menjawab **ya, berfungsi untuk Farm sandbox bounded**, tetapi **tidak** sebagai world/NPC production-grade. Sistem inti yang disebut di atas terhubung dalam `NeoRuntime` untuk Farm; prompt/doc intake merupakan jalur host-side yang terpisah dan Android baru mencapai toolchain preflight. Renderer Vulkan, packaging Android, multiplayer, serta operational backend belum terintegrasi sebagai produk rilis.

Langkah berikutnya adalah menghubungkan output prompt plan yang tervalidasi ke worker tersandbox dengan allowlist operasi, budget, cancellation, dan evidence yang dapat diaudit. Perbaikan Android harus terlebih dahulu memigrasikan CMake scaffold ke `Source/NeoEngine` kanonis dan menjalankan debug/device tests sebelum build artifact dipertimbangkan. Semua mutasi source/build/test harus tetap menghasilkan plan, evidence, dan approval; tidak ada model AI, dokumen untrusted, Coba, atau Aries yang memperoleh authority langsung terhadap economy, ban, player session, atau runtime game.

`AssetRefreshDiagnostics` menambah rencana tindakan read-only di atas dependency impact yang sudah ada. Ia memeriksa freshness staging texture/mesh/material dan provenance source pada `SceneMeshAdapter`, lalu hanya melaporkan tindakan refresh atau rebind yang harus dipanggil pihak luar secara eksplisit. Smoke membuktikan perubahan byte mesh menghasilkan `RefreshMesh` dan `RebindSceneInstance`, perubahan byte material menghasilkan `RefreshMaterial` dan `RebindSceneInstance`, dan perubahan byte texture menghasilkan `RefreshTexture` serta rebind untuk instance yang merekam provenance texture; tidak satu pun mengganti hash staged atau frame scene sampai caller melakukan rebind. `SceneMeshAdapter` kini menyalin texture ke ownership instance dan mengganti pointer material ke copy itu, sehingga ia tidak bergantung pada lifetime staging. `AssetRefreshExecutor` dapat menjalankan plan yang sudah dibangun caller secara berurutan, mengeluarkan receipt per action, dan berhenti pada kegagalan pertama tanpa menjalankan action sesudahnya; action sebelumnya tetap applied dan tidak ada rollback transaksi. Preflight executor sekarang menjalankan probe decode/import kandidat pada staging texture/mesh/material tanpa mutasi, sehingga replacement malformed dapat ditolak sebelum executor; setiap action juga terikat pada content hash registry saat plan dibuat dan ditolak bila hash tersebut sudah berubah. Action duplikat pada target staging atau entity scene juga ditolak sebelum receipt dan mutasi. Executor menjalankan gate preflight tersebut sendiri sebelum loop mutasi, dan rebind turut membangun kandidat `SceneMeshAdapter` copy-on-register tanpa mutasi sebelum diterima. Ini masih bukan jaminan transaksi lintas action setelah loop dimulai, rollback, lock registry, sinkronisasi concurrent, ataupun analisis konflik dependency umum. Secara keseluruhan ini meningkatkan observabilitas dan eksekusi lifecycle asset CPU yang eksplisit, tetapi tidak menyediakan file watcher, executor otomatis, queue background, invalidasi cache, propagasi lintas-instance, import texture-map material umum, maupun upload/present GPU.
